# 车况悬浮助手 OBD（ObdGauge）

**纯 OBD 方案**的车况悬浮显示应用：通过 ELM327 兼容的 OBD-II 蓝牙读头直接读取
CAN 总线标准信号（公开 SAE J1979 协议，另含比亚迪厂商自定义 PID 支持），
**不依赖比亚迪车机 SDK 与任何系统签名**，任意车型（含混动/纯电）可用。
本 APP 使用 GLM 5.3 Flash 编写，经测试在**比亚迪宋 Pro 2025 智驾版 + Vgate iCar Pro 2S** 上可以读取数据，已验证**发动机转速、水温、电池电量 SOC、电池功率、电瓶电压、进气温度、发动机负载**数据采集基本与实际一致，其余数据未测试，可能存在不可用或失真情况。

悬浮窗除中控屏外还可**投到仪表屏**显示：已在**比亚迪 DiLink 100（23 控制器）**车机上实测可用——免 root、免 ADB、不用车机 SDK，仪表上默认贴底居中，外观可切换成贴合原厂的「仪表风」。

## 功能

### 数据采集（均为公开协议）
| 数据项 | PID | 公式 |
|---|---|---|
| 发动机转速 | 标准 `010C` | ((A×256)+B)/4 |
| 油量 | 标准 `012F` | 100×A/255（支持校准系数） |
| 车速 | 标准 `010D` | A |
| 水温 | 标准 `0105` | A−40 |
| 电池电量 SOC | **比亚迪私有 `221FFC`**（mode 22 DID FFC，应答 61FFC 后首字节即百分数），不支持时回退标准混动 `015B` | 100×A/256 |
| 电池功率 | **优先比亚迪私有 `220008`（电池总电压）+ `220009`（电池电流）**，U×I/1000（与 OVMS / Battery-Emulator 一致）；**无应答时回退标准混动 PID `019A`**（电压取第 1 对字节 /10 V，电流取第 3 对字节有符号 /10 A——实测第五代 DM-i 标定：第 2 对为状态值恒 0，EHS 与 BMS 同时应答时按电压/电流合理性剔除 EHS、取 BMS，物理寻址 7E7 优先）。功能寻址不动寻址头；物理寻址临时切 7E7 并用 `ATSH7DF` 恢复（部分读头固件不支持无参 ATSH，恢复失败会导致标准 PID 全部失联）；连接初始化配置 ISO-TP 流控帧（`ATFCSH7E7;ATFCSD300000;ATFCSM1`）。放电正数、充电负数，单位 kW；全部无应答时显示 `--` 并弹窗展示探测记录，且**不锁死状态、每 5 轮自动重探**（适配解锁后仅低压上电、踩刹车才上高压的场景：上高压后 ~10s 内自动恢复） | U×I/1000 |
| 电瓶电压 | 标准 `0142` | ((A×256)+B)/1000 |
| 进气温度 | 标准 `010F` | A−40 |
| 发动机负载 | 标准 `0104` | 100×A/255 |
| 节气门开度 | 标准 `0111` | 100×A/255 |
| 机油温度 | 标准 `015C` | A−40 |

- 轮询按「悬浮窗启用项 + 转速/油量（主界面必需）」构建列表逐项请求，一轮结束立即下一轮；
  ECU 不支持的 PID 显示 `--`，短暂丢包保留旧值。
- 比亚迪私有 PID 来自社区公开资料（WiCAN / CarScanner / OVMS 生态通用做法），仅当用户勾选
  「电池电量」「电池功率」时才会发送，不影响其他车型。

### 悬浮窗
- **目标屏幕可选（中控屏 / 仪表屏）** —— 已在比亚迪 **DiLink 100（23 控制器）**车机上实测可用：
  比亚迪 DiLink 车机的仪表是由车机 Android 里的「投屏面」渲染的（原厂
  `com.xdja.containerservice` 用 `createVirtualDisplay` 建出的虚拟屏：DiLink 3 为 display 1、
  DiLink 5/DiLink 100 常见 display 2，名字形如 `fission_bg_xdjaVirtualSurface` /
  `fission_bg_XDJAScreenProjection`）。只要系统把它作为 **公开屏幕**暴露出来，第三方应用
  （无需系统签名、免 root、不用比亚迪 SDK）就能把窗口画上去：本应用用 `createDisplayContext()`
  取该屏自己的 `WindowManager`，窗口类型仍是 `TYPE_APPLICATION_OVERLAY`。
  在「悬浮窗显示屏幕」里会列出本应用能看到的全部屏幕（含分辨率；名字带 `xdja`/`fission` 的
  标注为「疑似仪表投屏面」），选中前先实测该屏能否加窗（与真正投屏同一套 API），成功才切换。
  **投屏到仪表时位置默认贴底居中**（垂直 100%），仍可在「水平/垂直位置」里调，且
  **中控屏与仪表屏各自记忆位置**。若车机没把仪表暴露出来（列表里只有屏幕 0）或加窗被系统拒绝，
  自动回退中控屏，原因记录在「诊断日志」（可复制反馈）。
- **多屏联动**：熄火/休眠时仪表投屏面会从系统里消失，服务按 `DisplayManager` 回调把悬浮窗
  自动收回中控屏，屏幕回来后自动再投；目标屏幕消失期间不影响其他功能。
- **自定义位置**：在 APP 内按屏幕百分比（水平/垂直 0–100%）调节，悬浮窗实时移动；
  中控屏默认顶部居中、仪表屏默认贴底居中。悬浮窗不可触摸（`FLAG_NOT_TOUCHABLE` 完全穿透），
  因此位置只能在 APP 内调，无法拖动。
- **自定义显示内容**：转速/油量/车速/水温/电池电量/电池功率/电压/进气温度/负载/节气门/机油温度
  十一项自由勾选；**显示顺序可调**（「悬浮窗排序」中上移/下移，悬浮窗、主界面列表同步生效）；
  **每行项数 1–4 可调**，超出自动换行。
  - 实现说明：部分旧车机（Android 5/6）的 WindowManager 对嵌套 `WRAP_CONTENT`
    窗口测量异常，多行时内容宽度塌缩。悬浮窗因此不依赖系统 wrap_content 测量，
    而是显式测量内容后把窗口设为**精确尺寸**，内容/字号/数值变化时重新测量
    （见 `FloatingService.relayoutWindow()`）。
- **字体**：内置三款免费商用字体（阿里巴巴普惠体、OPPO Sans、Orbitron 数字风），
  也可通过系统文件选择器导入自己的 ttf/otf 字体文件。数值字体与小标签字体独立设置
  （标签可选与系统一致 / 与数值一致 / 自定义文件；西文字体不含中文，标签会显示方块）。
  字体许可见 `app/src/main/assets/fonts/LICENSE.txt`。
- **样式可切换（卡片 / 仪表风）**：卡片风＝深色圆角底 + 细边框 + 粗字重（中控屏默认）；
  **仪表风＝完全透明底、无边框、系统细字重（sans-serif-light）、更淡更短的分隔线、
  更小内边距**（仪表屏默认），用来贴合原厂仪表信息的观感。字体若显式选过则不受样式影响。
- 字体大小 **6–48sp**（`−/+` 按钮与滑块）；**字号与样式都按屏幕分别记忆**：
  中控屏默认 24sp / 卡片风，仪表屏默认 10sp / 仪表风（仪表屏常见 1280×480@320dpi，
  同样的 sp 在中控屏偏小、在仪表屏偏大，所以给了更低的下限与独立记忆）。
  字号/颜色/位置/样式修改即时生效（前台服务监听 SharedPreferences 变化）。
  实测：仪表上「仪表风 + 10sp」的组合与原厂信息（SOC、里程、能耗那一排）观感接近，
  6–10sp 之间可按需再调。
- **主界面数据列表与悬浮窗显示内容保持一致**：勾选哪些项，两处就显示哪些项
  （主界面在 `MainActivity.rebuildMainMetrics()` 动态生成）。

### 其他
- **应用内扫描选择读头**：比亚迪等车机的系统蓝牙界面通常只显示"手机"类设备，读头无法在系统设置里配对。
  本应用自带经典蓝牙扫描，可直接列出附近**未配对**的读头（如 `Android-Vlink`）并选中；
  连接时走 RFCOMM，未配对设备会自动触发系统配对请求（Vgate 出厂配对码 `1234`），
  若车机不弹配对框则回退为免认证（insecure）串口——多数 ELM327 读头（含 Vgate iCar Pro 2S）接受。
- **油量校准**：OBD PID 012F 是 ECU 标准线性化值（100×A/255），与仪表/比亚迪 APP 的私有 CAN 油量存在固有
  偏差（典型几个百分点）。在「油量校准」中输入比亚迪 APP 当前显示的百分比，应用按比例对齐
  （显示值 = 公式值 × 系数，可随时「清除校准」）。
- **功率校准**：解码功率与仪表可能存在固定比例偏差（实测纯电行驶时 019A 读取值 ≈ 仪表 × 1/1.5，
  即读取 4kW 时仪表 6kW）。在「功率校准」中输入补偿倍率（0.3–3.0，如 1.5），
  显示值 = 解码值 × 倍率，放电/充电正负值按同比例缩放，可随时「清除校准」。
- **前台服务保活**（`START_STICKY` + 最低优先级通知）、**开机自启**（可选）、**断线自动重连**；
  未手动选设备时按名称自动识别常见读头（OBD/ELM/Vgate…）。

## 使用步骤

1. ELM327 蓝牙读头插入方向盘下方 OBD-II 接口（通电后读头指示灯亮起）
2. 安装 APK，打开应用（Android 12+ 会申请蓝牙权限，点允许）
3. 点击「OBD 读头设备」行：弹窗会列出已配对设备并**自动扫描**附近未配对读头，
   选择 `Android-Vlink`（Vgate iCar Pro 2S）；若弹出配对请求请确认（配对码 `1234`）。
   无需先去系统蓝牙设置配对——车机系统蓝牙不显示读头也没关系
4. 打开「启用悬浮窗」（首次需授予「显示在其他应用上层」权限）
5. 按需在「悬浮窗显示内容」「悬浮窗排序」「每行项数」「悬浮窗样式」「悬浮窗显示屏幕」「水平/垂直位置」「悬浮窗字体」中自定义

提示：
- 想把悬浮窗放到仪表上：在「悬浮窗显示屏幕」里选择仪表屏（分辨率与中控不同、系统名字里带
  `xdja`/`fission` 的一般就是它）。选中会先弹风险确认，再实测该屏能否加窗，失败会明确提示并留在
  中控屏。**部分车机需要先在原厂导航里把导航投到仪表一次**，那块投屏面才会常驻可用；
  DiLink 4.0 的部分固件只把屏幕 0 暴露给第三方应用，这种情况本应用看不到仪表屏，属系统限制。
  仪表上默认组合是「仪表风 + 10sp」（透明底细字重、贴底居中）；嫌大嫌小就在「悬浮窗样式」
  与字号里调，字号下限 6sp（仪表常见 1280×480@320dpi，6–10sp 大约对应原厂仪表的字号）。
- 混动/纯电优先车型发动机熄火时转速显示 0 或 `--` 属正常。
- 油量：部分车型（比亚迪常见，尤其混动/新能源）ECU 不实现 PID 012F，会以 `0xFF`（255）填充应答。
  本应用按 SAE J1979 公式换算（100×A/255），且原始字节连续为 0xFF 时判定为无效数据，油量显示 `--`，
  属车型限制而非读头故障；油箱真正加满时短暂出现的 0xFF 不受影响。
- 电池电量（SOC）：勾选后每轮先发比亚迪 `221FFC`，无应答再试标准 `015B`。
  不同车型（秦/汉/唐/宋/海豹等）应答的 ECU 可能不同，若显示 `--` 说明该车不支持该命令。
  成功后记忆有效来源（如仅 `015B` 可用的车不再每轮空发 `221FFC`），来源连续 5 轮失效
  自动回到双来源探测，不锁死。
- 电池功率：按探测链自动适配——① 比亚迪私有 DID `220008`/`220009`（功能寻址 → 物理寻址 7E7）；
  ② 标准 J1979 混动 PID `019A`（实测第五代 DM-i 可用：BMS 报电池包电压/电流，EHS 同时报升压
  母线电压。电流取第 3 对字节有符号 /10 A——已按实车标定：P 档上电 + 空调、仪表 ≈1kW 场景下
  第 2 对字节恒 0 不能用；EHS 应答按电压/电流合理性剔除，多应答取最后一个通过者 = BMS）。
  功率为负表示正在充电（动能回收/行车发电），为正表示放电驱动。物理寻址后必须用
  **带参 `ATSH7DF`** 恢复（部分读头固件如 Vgate iCar Pro 2S 不支持无参 `ATSH`，恢复失败会让
  寻址头滞留 7E7、所有标准 PID 失联、连接反复重建）。连接初始化配置 ISO-TP 流控帧
  （`ATFCSH7E7;ATFCSD300000;ATFCSM1`，BMS 多帧应答必需）。全部无应答时不锁死状态、
  每 5 轮自动重探（实测：解锁后仅低压上电时 BMS 的 019A 应答不完整——连续帧迟到被
  读超时截断，探测会失败；踩刹车上了高压后即恢复完整应答，无需重连即自动接上），
  并弹窗展示探测记录（可复制反馈适配）。**取值方式成功后持久化记忆**：下次启动
  直接按记忆方式读取（首发即出值、省去探测）；记忆方式连续 5 轮失效（上电状态
  变化/OTA 后失效）自动回到探测链重新适配，无需手动干预。
- 电机转速：DM-i 的驱动电机转速**没有公开的 ELM327 可用 PID**（标准 010C 只报发动机转速），
  社区资料（[opendbc-byd](https://github.com/BYDcar/opendbc-byd)）只有 2015 款唐 PHEV 的
  原始 CAN 解码，需要 CANable 等硬件抓帧，无法用读头直接查询。若后续拿到目标车型的
  CAN 抓包（如 Car Scanner 录制），可按厂商 mode 22 DID 扩展。
- Android 11 及以下系统的蓝牙扫描受系统限制需授予定位权限（已内置申请）。

## 稳定性与已知限制

- **悬浮窗自动拉起**：车机开机自启（BOOT_COMPLETED）常被 DiLink 限制；作为兜底，
  只要悬浮窗开关是开着的，打开 APP 即自动拉起悬浮窗（无需手动关开开关）。
- **崩溃反馈**：应用内置崩溃捕获（`CrashGuard`），未捕获异常写入私有目录并在
  下次启动时弹窗展示堆栈，便于现场拍照反馈（车机无法连 ADB）。
- **开机自启**：通过 `setComponentEnabledSetting` 启停 BOOT 接收器；部分车机固件
  会拦截自启广播，属系统限制。
- **投屏到仪表屏的条件与风险**：已在**比亚迪 DiLink 100（23 控制器）**车机上实测通过——
  仪表投屏面对第三方应用可见，悬浮窗可直接画到仪表上，无需 ADB / root / 系统签名。
  但仍取决于车机固件是否把仪表作为公开屏幕暴露给第三方应用（DiLink 5.0 / DiLink 100
  实测可以；部分 DiLink 4.0 固件只返回屏幕 0，须由 ADB shell 侧枚举，属系统限制），
  以及那块投屏面是否已被原厂导航激活（部分车机需先在原车导航里投一次）。悬浮窗是小尺寸、
  完全触摸穿透的窗口，但会盖住仪表原有画面的一小块（默认贴底居中）；若仪表显示异常，
  在中控屏把「悬浮窗显示屏幕」改回「中控屏」即可。本应用只加自己的 overlay 窗口：不写投屏面、
  不做任务迁移、不改屏幕密度，因此不会干预原厂仪表 / Qt 渲染流程，也不需要 ADB 或 root
  （社区同类工具把应用投到仪表时依赖 ADB 守护进程与任务迁移，本应用不涉及）。
  熄火/休眠导致仪表屏从系统消失时，服务会按 `DisplayManager` 回调自动把悬浮窗收回中控屏，
  屏幕回来后自动再投。

## 工程结构

```
ObdGauge/app/src/main/java/com/cloudwolf/obdgauge/
├── MainActivity.java     # 主界面：实时数据 / OBD 设备 / 悬浮窗位置、内容、排序、字体、目标屏幕设置 / 油量校准
├── FloatingService.java  # 悬浮窗（百分比定位 + 动态内容行列 + 字体应用 + 中控/仪表多屏投送）+ 前台服务
├── DisplayUtil.java      # 多屏支持（枚举车机屏幕、识别仪表投屏面、加窗探测、投屏诊断日志）
├── ObdClient.java        # ELM327 客户端（多 PID 轮询、比亚迪 221FFC/220008/220009、重连）
├── GaugeItem.java        # 可显示数据项定义（PID、公式、文案）
├── FontUtil.java         # 内置/自定义字体解析与缓存（含仪表风用的系统细体）
├── BootReceiver.java     # 开机自启
└── Prefs.java            # 设置持久化（显示项顺序、功率/SOC 取值方式、目标屏幕与按屏的字号/样式/位置）
```

依赖仅 `appcompat` + `material`；`minSdk 21`、`targetSdk 33`（覆盖 Android 5.0+ 的全部 DiLink 车机，v1+v2 双签名保证 Android 7 以下可安装）。
内置字体位于 `app/src/main/assets/fonts/`（约 20MB，含许可说明）。

## 构建

```bash
gradlew.bat assembleDebug     # 调试包
gradlew.bat assembleRelease   # 发布包（默认使用 debug 签名，可直接安装；
                              # 如需自有签名：-PSTORE_FILE=xx.jks -PSTORE_PASSWORD=xx -PKEY_ALIAS=xx -PKEY_PASSWORD=xx）
```

命令行构建需设置 `JAVA_HOME`（如 `C:\Program Files\Android\Android Studio\jbr`）。

- **新增「悬浮窗样式」**：卡片风（原样式）/ **仪表风**（透明底、无边框、系统细字重、淡分隔线），
  仪表屏默认仪表风；位置、字号、样式均**按屏幕分别记忆**（仪表默认贴底居中、10sp）。
- **字号范围由 12–48sp 放宽到 6–48sp**（仪表屏分辨率低，12sp 在仪表上已明显偏大），
  并修正小标签字号算法（原来最小 9sp，字号调小时标签会比数值还大）。
